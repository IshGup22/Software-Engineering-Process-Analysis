# BPMN Process Maps

This folder contains the current-state and future-state BPMN-style process models for the software change request workflow.

## Current State

The current-state workflow highlights:

- Email-based request intake and clarification
- Manual requirements review
- Repeated clarification loops
- Spreadsheet/backlog tracking
- Manual prioritization
- Testing expectations defined later in delivery
- Email-based release confirmation

## Future State

The future-state workflow introduces:

- Standardized request intake
- Upfront requirement validation
- Earlier definition of requirements and acceptance needs
- Structured engineering feasibility review
- Jira-based backlog tracking
- Backlog prioritization and sprint planning
- Testing directly against acceptance criteria
- Formal business acceptance and release readiness

The future-state design is intended to improve process consistency, traceability, ownership, and delivery visibility.
